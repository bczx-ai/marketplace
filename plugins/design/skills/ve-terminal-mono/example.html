01

为何是现在

设计是技术栈里最后一个没被脚本化的工具

Q3 2026 培训积压

工程师早已把其他一切都脚本化

  • 部署、迁移与 CI 都从终端运行 —— 而设计仍然意味着一只鼠标和一个共享的 Figma 席位
  • 新员工会问，为什么代码有 git，设计工作却没有对应物
  • 智能体原生的 CLI（Claude Code、Codex、Cursor）如今已活在每个工程师的 shell 里
  • 没有任何入职路径把设计当作流水线中可脚本化、由智能体驱动的一环来教

之前 —— GUI 习惯

一位设计师，一块屏幕

  • 每个需求都排在一个 Figma 席位后面
  • 无法为重复布局做模板或脚本
  • 交接就是把截图丢进 Slack
  • 没有「谁在何时改了什么」的审计轨迹

试点 —— 第 1–6 周

任何工程师，一条命令

  • 第一周有 14 位工程师运行了 od project create，零入职工单
  • 设计规格以可 git diff 的文件形式存在，在普通 PR 中评审
  • od plugin apply 能在 90 秒内用设计系统脚本化一整个页面
  • 完整的 shell 历史兼作变更审计轨迹

先教这五条命令

od-101.md 
[week 1]
init     = "od project create <name>"     # first command every hire runs
import   = "od design import <repo>"
[week 2]
run      = "od agent run --prompt-file brief.md" # --json pipes into CI
apply    = "od plugin apply <template>"
[week 3]
ship     = "od file export --to ./dist"       # git-diffable, PR-ready
>
当 od agent run --json 能干净地接入我们的 CI 那一刻，设计不再是这条本已脚本化的技术栈里唯一的 GUI 例外。
