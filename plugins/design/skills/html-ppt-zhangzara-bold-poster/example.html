解决方案
2026 年 4 月，Claude Design 证明了 LLM 真的能设计——不是写关于设计的文字，而是产出真实产物。它以闭源、付费、纯云端的形式发布：单一模型、没有 agent 选择、无法自托管、不支持 BYOK。这个缺口就是我们的全部楔子。

Open Design 把这种能力释放出来： Apache-2.0，运行在构建者自己的机器上， BYOK，没有注册墙。
我们没有重建 agent——我们把 Claude Code, Codex, and Cursor——这些已经装在构建者机器上的东西——接入一条完整的设计工作流。分发是免费的，因为每一次安装都是一位已经解决了最难部分的开发者。

每一次会话都在复利：设计系统、偏好与记忆把一次性用户变成护城河，而不是注册后就开始漏的漏斗。

楔子：我们从哪里切入
原型
阻力最小的切入点：构建者描述一个界面，得到可真实运行的原型，全程不离开自己的机器。
  • 移动端与 Web 流程
  • 交互状态，而非静态图片
  • 即时沙箱预览与编辑
  • 首次会话零注册
幻灯片
向团队扩张的动作：演示文稿与看板被分享出去，每一次分享都是一位新构建者发现这个楔子。
  • 创意演示文稿
  • 研究报告
  • 互动看板
  • 把同事拉进来的实时简报
图片
护城河在此成形：一旦导入了设计系统，生成的每张图片都锁定在该工作区自己的调色板与品味上。
  • 海报
  • 插画
  • 产品效果图
  • 每次都保持品牌一致的输出
视频
ACV 最高的界面：HyperFrames 把设计工作区变成营销生产线，这是我们下一步变现的增购项。
  • HyperFrames HTML 转 MP4 流水线
  • 营销短片
  • 产品演示
  • 电影感生成素材
动作一 — 切入
一位构建者，零阻力
一位开发者本地安装，用一句话描述目标，在任何销售对话发生之前就拿到可用的产物。
  • 224+ 个插件作为即时起点
  • 本地文件、Figma 导出与仓库皆可读取
  • 与机器上已有的 agent 协同
  • 意图与产出之间没有注册墙
动作二 — 标准化
团队导入一套系统
第一次共同胜利带来一次设计系统导入——已有 131 次并持续增加——整个团队现在默认生成符合品牌的内容。
  • 从 GitHub、Figma 或本地文件导入
  • Markdown 设计系统能阻止 token 漂移
  • 调色板、字体与间距自动应用
  • 每次运行都强制品牌一致性
动作三 — 复利
记忆变成切换成本
每一次会话都会写回偏好与记忆，因此工作区对这个团队的品味把握得越来越好——也越来越难以离开。
  • 真实可运行、可 git diff 的文件
  • 即时沙箱预览与编辑
  • 每个工作区自我演进的设计记忆
  • 每次运行都更贴近团队想要的结果
动作四 — 扩张
视频打开增购空间
HyperFrames 把同一个工作区变成营销生产线——在免费核心之上变现的、按席位计费且 ACV 更高的界面。

为什么这是风投级别的机会
TAM 入口
每一个编程 agent 席位
我们不与 agent 竞争，而是凌驾于它们之上——Claude Code、Codex CLI、Cursor Agent、Gemini CLI 等等。任意 OpenAI / Azure / Google 端点都可通过 BYOK 接入，因此我们的 TAM 是整个 agent 编程市场，而不是某一家厂商的装机量。
