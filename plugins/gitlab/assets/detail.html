GITLAB CLI

从代码审查到发布，直接调用 glab

让 Agent 使用 GitLab 官方 CLI 理解当前仓库，处理 Issue、Merge Request、pipeline、job、Release 与 GitLab API。

官方 glab CLI自动识别仓库上下文高影响操作确认

01 / 功能

覆盖核心工作对象

Issue 与 MR

搜索事项、查看差异与评审状态，在确认后创建、评论或审批。

CI/CD 排障

查看 pipeline、job 和日志，定位失败阶段并整理可执行修复建议。

项目与发布

查询项目、成员和 Release，并通过同源 API 补足专用命令未覆盖的能力。

02 / 使用场景

可以直接这样说

“审查当前项目待合并的 MR，汇总变更风险和阻塞项。”
“分析最近失败的 pipeline 和 job 日志，定位首个有效错误。”
“根据当前改动创建 Issue 或 MR，提交前先确认标题和描述。”

WORKING BOUNDARY

变更落在明确的项目边界内

MR、Issue、Pipeline、Release 和 API 操作遵循当前 GitLab 身份与项目权限，写操作保留可审查上下文。
